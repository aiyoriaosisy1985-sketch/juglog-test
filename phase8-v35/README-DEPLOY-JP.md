# 既存GitHub検証サイト・上書き候補 v3.5 (iPhone QA)

**本番Netlifyサイトに配置しない。** GitHub Pages の既存検証repoだけが対象。既存272件を意図的に初期化／復元しない。

## 先に確認すること
1. GitHub既存検証サイトの現在のリポジトリから、現在のファイルを手元へZIPでバックアップ。可能なら現行commit IDを記録。GitHubのコミット履歴が残っていることも確認。
2. 以前提供された272件のJSONバックアップは内部監査で存在確認済み。ただし **最新版と一致する保証はない**。既存サイトから最新版をエクスポートできる場合は、そのJSONを別途保存する。個人データの混入を避けるため、この配布ZIPにはバックアップJSONを含めていない。
3. 過去のGitHub PagesサイトのService Workerがある場合は挙動を確認。今回のパッケージは新しいService Workerを登録しないが、既存の制御は解除されない場合がある。
4. 旧サイトと同一originにあるため同一ストレージ名前空間。v3.5アプリのDB名／localStorageキーは既存のP31 QA版等から分離済み。ただし、ブラウザのサイトデータ削除をすると同一origin全体が削除される。絶対に行わない。

## 配置時
- v3.5 ZIPのルートにある実行用の `index.html`,`p31.html`, `.js`, `.css`, アイコンをGitHub既存検証repoのルートへアップロードして更新。GitHub上で**削除／Remove directory／リポジトリ削除をしない**。
- README/報告JSON/バックアップは実行ファイルではないためサイトへの公開アップロードは不要。バックアップJSONは **GitHubへアップロードしない**（公開repoなら誰でも閲覧可能）。
- GitHub Pagesのデプロイ完了を確認。既存検証URLは変えない。
- Safariで一度リロードし、5タブとアプリの見た目を確認してから架空の新規実戦を作る。
- 最初に旧272件をインポート／復元しない。設定内の「サイトデータ削除」や「全データ削除」を使わない。
- 操作と保存結果が不明な時は二度押ししない。端末画面と時刻を記録して試験停止。

## 統合設計上の限定
- v3.5はv3.4の**P31内DB名とlocalStorageキーの名前空間変更のみ**。新機能なし。
- 旧GitHub検証サイトの現行公開ファイルはこの環境で未入手のため、そのファイルの絶対的な不変性と、完全ロールバック可能性は**未確定**。旧版のバックアップが必要。
- P31本体以外の `safety-test.js` は実行すると自身が生成したランダムDBを削除するテストを持つ。既存の272件DBを対象にしないが、検証中に安全性テストをむやみに実行しない。
- 画像・IndexedDB保存・Undo・再読み込みの実機テストは未実施。ZIPの静的監査だけでは完全な安全は保証できない。
