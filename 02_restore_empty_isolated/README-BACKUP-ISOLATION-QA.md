# バックアップ・復元 隔離QA（2026-10-27）

## データ保護
この候補は `p31.html` の IndexedDB 名 `juglog_backup_restore_isolated_20261027_db` と関連する localStorage キーを、従来の 997・1001番台用キーから変更した専用版です。**実機では未検証**です。元のGitHub検証フォルダー `phase8-design-finish-qa` に上書きしないでください。必ず新規の専用フォルダーを使います。Netlify本番v45は変更しません。

## 一連の試験（テストデータのみ）
1. 空の隔離DBで、実戦を一件作成。100G・BB1回など少量の操作と取消・復元イベントを記録。
2. JSONを書き出し、端末に実際のファイルがあること、manifestのイベント数・チェックポイント数を確認。
3. 同じJSONを読み込む。形式検証は成功するが、**イベントのあるDBへの復元は拒否**されることを確認。
4. 別の空DB（さらに別の保存キーを持つ試験環境）で復元し、イベントID・順序・取消状態・チェックポイントが原本と一致するか照合する。
5. イベント数不一致、重複ID、不正な取消参照などの破損JSONが復元前に拒否されることを確認。
6. 復元結果が不明な際に再実行せず、読み込みと照合に切り替わることを確認。

## 注意
- このZIPだけでは手順4の**第二の空DB**は用意していません。復元成功検証用には別名のDBを持つ受け側ビルドが必要です。
- 同じGitHub Pagesホストでフォルダーを分けただけではIndexedDBは分離されません。
- この候補のテストは本番データに触れずに行うことが目的で、復元機能の合格を意味しません。
